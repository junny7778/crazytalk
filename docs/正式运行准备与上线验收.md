建议将 Demo、验收和生产分为独立地址、数据库、附件目录及凭证。Demo继续原演示数据，生产从空库初始化，不复制当前“验收”学员或测试账号。新登录页验收由其他Agent完成，不重复纳入本清单。

## 初始化与切换

启动API使用 pnpm --filter @crazytalk/api start（tsx运行，无watch；当前tsx在devDependencies，服务器需安装完整锁定依赖）。静态构建使用 pnpm --filter @crazytalk/admin build:business 及 pnpm --filter @crazytalk/teacher build:business。生产环境必须显式设置NODE_ENV=production；不使用开发watch服务器。

在最终服务器和发布目录确定后，先锁定版本和依赖，再由运维设置服务环境变量：DATABASE_URL、API_PORT、BUSINESS_ORIGIN、NODE_ENV、UPLOAD_DIRECTORY、CLASSIN_DATA_DIRECTORY及ClassIn配置。不要把值写入工单、日志或前端产物。

在仓库目录执行迁移和初始化（仅在已确认目标为空的正式数据库、正式部署授权后）：

```sh
pnpm --filter @crazytalk/api exec prisma migrate deploy
pnpm --filter @crazytalk/api exec tsx src/bootstrap.ts
```

bootstrap需要通过服务环境安全注入BOOTSTRAP_LOGIN、BOOTSTRAP_PASSWORD（至少8位）、可选BOOTSTRAP_NAME；已有账号会拒绝再次初始化。完成后移除bootstrap口令环境变量。创建实际岗位角色、账号与老师teacherId绑定，验证管理员/教务/老师范围。正式基础数据导入先在验收环境试导，核对账号—学员—共享余额关系和期初余额；正式库禁止加载Demo种子。

## 数据库与附件备份恢复

以下变量是执行时填写的占位，不预设服务器路径。要求 PostgreSQL 客户端与服务端兼容，备份目录仅运行用户可读，密钥通过PGSERVICE/PGPASSFILE注入而非命令行明文。

先阻止新业务写入，并停止API进程及其内置worker，取得同一停写窗口的数据库和附件副本：

```sh
umask 077
export PGSERVICE=crazytalk-production
pg_dump --format=custom --file="$CT_BACKUP_DIR/database.dump"
tar -C "$UPLOAD_DIRECTORY" -czf "$CT_BACKUP_DIR/uploads.tar.gz" .
pg_restore --list "$CT_BACKUP_DIR/database.dump" > "$CT_BACKUP_DIR/database.contents"
shasum -a 256 "$CT_BACKUP_DIR/database.dump" "$CT_BACKUP_DIR/uploads.tar.gz" > "$CT_BACKUP_DIR/SHA256SUMS"
```

这里CT_BACKUP_DIR必须是预先创建、不会覆盖旧备份的日期目录。另存应用版本、迁移版本、文件权限及路径映射；凭证配置采用独立加密备份，不混入普通日志。停写窗口结束后恢复API。

恢复演练只对新建隔离空库执行；运维先创建目标数据库及固定附件目录，再设置PGSERVICE=crazytalk-restore指向该库：

```sh
pg_restore --exit-on-error --no-owner --dbname="service=crazytalk-restore" "$CT_BACKUP_DIR/database.dump"
tar -C "$CT_RESTORE_UPLOAD_DIR" -xzf "$CT_BACKUP_DIR/uploads.tar.gz"
```

附件目录必须与DB记录路径对应。演练容器可以挂载到原绝对路径；不要启动会使用真实ClassIn凭证的worker。验收：学员与订单数量、共享余额/流水、历史课节/反馈/薪资、附件图片和视频Range读取一致；关闭所有恢复出的旧会话后再开放。定时频率、保留期限、异地备份及可接受丢失时长由业务确认后配置。当前未执行备份或恢复演练。

## 进程、日志和监控

选定systemd或现有平台进程管理器后固定工作目录与环境文件；配置开机启动、退出重启、优雅停止时间、日志轮转及磁盘容量告警。当前代码有退出钩子等待进行中的worker/结算，不应直接强杀正常进程。监控至少覆盖/api/health、数据库连接、HTTP 5xx、附件剩余空间、备份最近成功时间、ClassIn failed/uncertain/blocked任务和未处理回调。告警渠道/负责人尚待确定；不得把SID、secret、密码、会话Cookie写入日志。

## 域名、TLS与ClassIn真实验收

1. 确认用户和ClassIn访问所需的服务器地域；设置管理端/老师端及API同源路由，签发TLS证书并配置续期。
2. 公网POST回调地址为HTTPS域名下的 `/api/webhooks/classin`；反向代理保留请求体，不能重定向POST或要求网页登录。其他业务写接口仍保留会话及来源校验。
3. 获取明确允许测试的老师UID、学员UID和机构成员关系；约定测试课程时间及名称。首次对外写前确认这些对象，不使用现有真实学员盲测。
4. 顺序验收建课→客户端可见→改课/换师→取消；核对本地外部ID映射。分别记录本地命令、同步日志和ClassIn结果。
5. 验收真实进入/出勤/结束回调，签名无效拒绝、有效重复通知不重复扣课、早到事件能关联。验证共享账号退款取消所有关联未来课节，保留账号历史。
6. 对未知请求结果恢复单独验收；只有外部ID和状态确认后才解除阻塞。不能用换唯一标识重建规避未知结果。

尚缺：公网回调地址和连通、测试UID及真实写入授权、正式域名/服务器参数、备份策略与告警联系人。只读凭证探测成功不等于真实排课验收。

## 发布与回滚关卡

发布前：模块测试通过、真实联调通过、备份恢复演练通过、正式账号权限核对、HTTPS与附件检查、完成版本及数据库快照登记。上线先少量真实业务核对后再扩大使用。

回滚前停止新写入；无数据库变更时回退兼容的应用版本。涉及迁移时先确认旧版本兼容，禁止盲目反向迁移或覆盖新业务数据；需要恢复快照时明确丢失时间窗，取得负责人确认。ClassIn已经发生的建改取消不会随数据库回滚，必须对账并恢复映射；不得直接恢复旧outbox重放外部操作。

# ClassIn 同步反馈与页面异常处理补充方案

状态：2026-11-20 已完成本地代码改造及专项验证。此版替代此前逐步进度、逐课计数、业务页面人工核实等交互设计。验证范围和真实平台未验证项见第 11 节。

## 1. 用户只看处理结果

普通操作仅展示处理中、成功、失败。按钮提交时禁用防重复；较长操作统一 loading，不展示内部步骤、成功/失败课节计数、重试次数及外部编号。

成功表示本次必要操作已实际确认完成，不能把本地任务入队当作 ClassIn 操作全部成功。失败直接解释原因和可执行的下一步。

|入口|处理过程|结束反馈|
|---|---|---|
|学员/老师/团队账号关联|关联按钮 loading|关联成功，或明确的账号/权限错误；不新增重试、分步进度面板|
|排课、追加课程|统一「正在排课」loading|排课完成，或明确错误；已完成课程保留，不能重复创建|
|改期、单节取消|统一「正在改期/取消」loading|完成或错误，不要求用户管理后台同步步骤|
|换老师|统一「正在取消原老师预约」loading|全部必要取消确认后提示可重新排课；未完成则提示错误，暂不允许提交新预约|
|换 ClassIn 账号|统一「正在更换账号」loading|完成或错误，不展示取消/余额/成员三个技术阶段；操作前仍解释余额去向|
|教务交接、添加成员|统一「正在交接/添加」loading|完成或错误；明确不能换班主任但已成功加入班级时按已定规则完成|
|停课/结课/退款|统一 loading|说明实际业务结果；外部取消失败不能误报整项完成，也不能重复退款|

确认前保留必要业务信息：换师选择原老师及影响范围、换账号确认共享余额去向、退款确认金额等。取消的是当前学员与选中原老师的尚未开课预约，其他老师不受影响。

## 2. 系统处理可重试失败

用户明确要求自动重试，覆盖此前“不增加自动重试”的一般约束，但仅限本次已确定的外部同步场景。

- 对暂时故障且确认可安全重试的操作，系统最多尝试 3 次（首次加 2 次重试），期间保持同一个 loading，不弹出每次失败。
- 余额不足、账号不存在、未关联账号、权限不足、资料缺失、时间冲突等明确业务错误直接提示，不重试。
- 修正业务问题后，用户可以再次提交正常操作，不新增独立重试面板。
- 请求超时可能意味着平台已经执行。已确认有去重保证的操作使用原标识继续；没有去重或查询保证的创建操作不得盲目重复。无法确认时给出最终错误并保留日志，不要求普通用户手填编号核实。
- 自动重试只继续未完成工作；成功课堂、余额转移、扣返和退款不重复执行。
- 批量操作部分完成而最终失败时，错误必须说明仍有未完成内容；保留实际已完成结果，不假装全部回滚。可用简短提示配既有课程列表查看，不新增逐项处理工作台。

## 3. Loading 的必要行为

Loading 根据后台实际结果结束，不使用固定时长模拟成功。刷新或离开页面不能丢失已提交任务；返回时恢复处理状态，防止重复提交。

换师/换账号的必要取消未确认时，仍阻止冲突的新预约。后台保留这些限制，但无需展示内部处理阶段。

## 4. 同步管理只保留日志

删除设置页「待核实的外部结果」「班级同步事项」独立大卡片，正常业务页不新增人工核实面板。

ClassIn 同步管理保留连接配置及统一日志，供管理员排查。正常教务不用进入日志完成日常操作。

收到无法匹配到本地对象的通知：保留原始日志，不弹提醒、不生成待办、不要求用户补历史数据，也不按共享 UID 猜学员。先到通知在关联记录建立后可沿用已有自动重放；长期无对应记录不阻塞正常业务。

已知课程的有效改期、取消等通知仍自动同步；无法安全归属或冲突的记录保留实际事实和日志，不误改其他课程或余额。

## 5. 验收重点

1. 所有入口提供简洁的 loading、成功或错误反馈，无逐步技术进度和逐课重试操作。
2. 本地提交成功但外部未完成时不能提示整项成功。
3. 暂时故障在安全条件下自动恢复；最多 3 次尝试；业务错误不重试。
4. 未知创建结果不重复建课；失败后的再次提交不重复成功课堂和余额操作。
5. 换师仅影响指定关系，换号共享课时去向不变，未完成时限制仍有效。
6. 部分失败如实反馈，刷新不丢任务，关联明确错误时保留用户输入。
7. 无匹配通知仅留日志，无弹窗/待办，不影响正常排课。
8. 移除旧卡片后仍保留管理员排查记录；自动重试能力须经过专项验证。

实施验证沿用原 CI/AC 编号，并按此版替换此前复杂页面状态要求。真实 ClassIn 联调仍单独记录，不以模拟成功代替。


## 6. 各操作的完成标准和错误文案

|操作|何时算成功|失败反馈示例及保留结果|
|---|---|---|
|关联账号|已确认已有账号并成功保存关联|「未找到该 ClassIn 账号，请检查手机号或邮箱」；保存失败保留输入和本次已取得的查验结果|
|排课/追加|本次必要班级、成员、课堂均已确认，映射已保存|余额不足直接指出不足；部分建课完成则提示「部分课程未排成，请在课程列表查看」，保留成功课堂及对应占用|
|改期|目标外部课堂时间已确认修改|「改期未完成」；保留申请时间和最近确认的外部时间，不误显示双方已一致|
|取消|外部确认取消，或有可靠依据确认课堂从未创建|「课程取消未完成，请稍后再试」；结果未知则「暂时无法确认取消结果，请联系管理员」，不允许按空闲时段重复占用|
|换老师|选定原关系的必要取消全部确认，对应占位处理完成|「原老师部分课程尚未取消，暂时无法重新排课」；不恢复已取消课程、不再重复取消成功项|
|换账号|目标账号已查验，必要取消完成，绑定/余额提交完成，必要班级成员替换完成|「账号更换未完成」并按实际情况补充「原账号仍保留」或「账号已更新，部分班级尚未更新」；不再次转移余额|
|交接教务|本地归属更新，所有相关班级新教务已加入；班主任按能力处理|「负责人已更新，部分 ClassIn 班级交接未完成」；不把超时视为明确不支持|
|添加成员|对应班级确认该成员已加入|「成员添加失败：该账号无权限」；不改主讲老师，不影响其他班级|
|服务变更/退款|按原业务规则完成本地事项，并确认本次必要外部事项|分别说明已完成的退款/服务变更和未完成的课程取消；不因重复提交再次执行金额或课时变动|

错误提示尽量包含对象、原因、下一步。接口错误码及技术细节放日志。业务错误修正后可再次使用正常提交按钮；若上次已有成功部分，系统先接续原操作，避免把重复点击当作一批全新课程。结果仍未知时禁用冲突操作并说明原因，不能鼓励用户反复点击重建。

## 7. 统一 loading 与页面退出

- 统一动效，仅使用「正在关联」「正在排课」「正在取消原预约」等业务文案，不显示技术步骤、百分比、重试次数。
- 从提交开始覆盖本次必要处理，不能本地入队就结束并报成功；即时校验失败不启动外部任务。
- 同一对象的重复/冲突按钮禁用，不锁住整个后台，其他学员的业务正常使用。
- 允许离开页面，已持久化任务继续执行；返回后读取同一操作结果。无需建设新的进度中心。
- 读取进度的网络失败与业务执行失败分别处理；暂时读不到结果不能自动重发业务命令。显示「暂时无法获取处理结果，请稍后查看」。
- 后台请求有超时限制、自动尝试有次数上限；达到明确失败或无法安全确认时结束 loading，展示错误，不无限转圈。
- 暂时失败的建议自动尝试间隔为 2 秒、5 秒，首次加两次共最多 3 次。批量数量多带来的等待使用同一个 loading，不给每节课做独立动效。

## 8. 数据及后台最小改动

复用现有课程、账号、班级、任务及日志，不重建任务平台、不引入新依赖。

1. 每次用户提交有稳定的操作标识；将该次取消、成员更新等已有任务关联起来，便于页面判断整体结果。已有可用 requestId 优先复用，缺少关联时只补必要字段。
2. 页面只取处理中/成功/失败及简短说明；后台保留任务步骤、成功部分、外部编号和原因用于续做及排查。
3. 将现有失败结果区分成明确业务拒绝、确认可安全重试的暂时失败、外部执行结果未知。不能把所有 HTTP 错误或超时一律自动重试。
4. 自动尝试次数持久化，刷新/重启不重置；只继续未完成工作，不重复账户余额转移、支付或课堂创建。
5. 旧请求晚返回不能覆盖较新操作；回调与主动请求共同确认同一目标，避免两个路径重复处理。
6. 原时段外部取消尚未确认时，冲突检查仍能识别未解除的外部占用。取消/改期失败不提前宣布外部时段释放。
7. 服务端权限与队组检查继续生效；页面简化不改变谁有权修改学员、课程或成员。

## 10. 范围与文档优先级

本方案不改变已确认的分班、共享余额、定向换师、教务交接及旧课保留规则。改变的是操作反馈、失败恢复和日志展示。

此前文档关于独立「待核实的外部结果」面板、逐节重试工作台、分步进度及未匹配通知待办的交互描述，以本方案为准；原测试通过记录仍只是当时版本证据，新自动重试和简化页面必须重新验证。

|学员详情、排课及相关业务页|返回页面读取原操作，一行处理状态/最终错误；可安全继续时使用「继续换老师/继续排课」等原业务动作|不显示逐课计数、步骤或技术编号；结果未知不提供盲重建按钮|
|ClassIn 同步管理|连接配置 + 统一同步日志；时间、对象、操作、结果、原因及直接展开的详情|删除两张独立卡片和旧异常重试工作台；未匹配通知只入日志|

### 后台与恢复规则

- 复用 AppliedCommand.requestId，ClassInJob 增加 operationId、retryAt；换号的后续成员任务继承同一个操作标识。
- 浏览器只保存命令摘要与请求标识，不保存密码或整条命令。并发重复点击复用同一请求；失败后继续只接续未完成任务，不再次运行本地扣返、退款或余额迁移。
- 对网络故障/HTTP 429、5xx，仅在已具备安全重复语义的建班、成员添加/移除、课堂取消和修改步骤自动尝试；总计最多 3 次，等待至少 2 秒、5 秒。现有 worker 轮询可能使实际间隔略长。
- 明确业务拒绝不自动重试。课堂创建、班主任修改等结果未知且没有确认恢复保证的步骤停止并提示错误；技术原因保留日志。进程中断的未知结果仍保守处理。
- 页面读取结果的单次请求有超时，连续等待超过两分钟改为“仍在处理中，可稍后查看”；后台任务继续，不能误报失败或重新创建批次。
- 普通用户不用处理技术核实表单；原有后台证据登记接口保留供维护使用。继续操作重新检查当前权限；日志与班级沿用队组数据隔离。
- 本地数据库已应用 `20261120020000_classin_feedback`，未部署生产。

## 12. 教务 / TM 账号关联入口简化（2026-11-20）

- 团队账号列表增加 ClassIn 账号列：未关联显示「关联」；已关联显示实际账号，不展示 UID；停用账号不能发起关联。
- 「编辑团队账号」只维护后台资料，移除内嵌关联表单。新建账号先保存，再从列表关联，避免在未保存的角色或姓名上发起外部操作。
- 独立「关联 ClassIn 账号」弹窗展示姓名和当前后台角色，仅保留手机号/邮箱、取消及确认关联。文案明确 ClassIn 账号可以与后台登录账号不同，关联不改变后台角色。
- 确认时统一「正在关联」；成功直接关闭弹窗并刷新列表，无需再次点击「保存账号」；失败保留表单和错误。
- 关联只使用已保存的账号资料，不携带账号编辑草稿。教务、TM 两种角色均覆盖专项测试；原学员/老师关联流程保持原业务规则。


## 13. 关联弹窗统一样式（后续调整）

学员、老师、教务和 TM 的关联弹窗统一采用学员中心样式：宽度 480px、标题不带姓名副标题、底部单个整行主操作按钮，通过右上角关闭。

内容顺序为姓名、角色（仅教务/TM）、ClassIn 账号输入框。三个字段统一为上方字段名、下方方框，每个字段独占一行。姓名和角色使用灰色禁用输入框，ClassIn 账号使用可编辑输入框；角色仅教务/TM 展示。学员先核实再确认的业务步骤以及共享课时/换号预览保持不变，其他角色的关联规则保持不变。本节替代第 12 节关于取消按钮及姓名角色放在副标题的布局描述。

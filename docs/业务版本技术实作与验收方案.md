# 业务版本技术实作与验收方案

2026-11-18 · 配套[产品功能地图](业务版本产品功能地图.md)。下文保留模块目标和验收要求；当前实现映射见本节。实际执行结果以[实施进度](业务版本实施进度.md)和[验收覆盖](业务版本验收覆盖.md)为准。

## 当前实现映射（本地开发）

- Demo 后台 `5173`，业务后台 `5175`，业务老师端 `5176`，API `3011`，PostgreSQL `55432`。业务前端同源 `/api` 代理至 API。尚未部署公网环境。
- `BusinessProvider` 和 `businessClient` 接入会话及命令；公开 `/intake/:token` 不经过登录墙。业务模式不启动 Demo 数据加载及浏览器结算。
- 为完整复用已有组件，本轮提供 `GET /api/state` 的授权范围 DTO 与 `POST /api/commands` 的显式判别联合命令。模块 REST 分页接口未实施；列表分页、统计和导出基于授权后的状态在现有页面计算。服务端仍独立校验所有写入，客户端不能提交任意整库状态。
- 订单、成员、课节、学员、老师、流水、报告等实体分别入表，关键关系和状态用列、外键与索引约束，其他现有表单字段保留 JSON。写入仅更新变化实体。PostgreSQL 事务与统一业务写锁确保跨订单及排课一致性，requestId 防止同一请求重复入账。
- Cookie 会话、CSRF、操作者覆盖、命令权限及实体范围、账号初始密码原子创建已接入。语言、培训、消息已读使用账号偏好。老师账号通过明确 teacherId 的初始化 CLI 绑定，不按名字猜身份。
- 本地附件存放 API `.data/uploads`，数据库记录所有者、大小和 MIME。流式上传及视频 Range 支持，读文件检查当前身份或可见业务引用。未配置生产对象存储。
- `ClassInJob` outbox 与本地业务同事务提交；后台 worker 调用外部 API。失败保留原因，结果未知阻断后续同课任务，不盲目重试。回调入箱验签去重，业务事件在数据库事务内处理。公网联调条件单列，不能用本地 mock 通过代替。

## 应用边界与数据访问

在 crazytalk-ops 新增 apps/api，采用 NestJS 模块化单体、Prisma 与 PostgreSQL。admin 和 teacher 保留当前路由、组件、表单及导航。在应用启动时由访问地址选择 Demo 或业务数据实现。生产业务地址使用同源 /api，Demo 使用自己的数据和独立问卷收件空间。演示域不配置业务库或 ClassIn 凭证。业务稳定后可移除 Demo 入口及提供器。

现有 useDemo 读取全量 DemoState，DemoProvider 定时结算，LocalRoster 在本地启动时加载工作簿。按模块把组件所需查询和动作提取为异步调用：Demo 实现委托现有 repository，业务实现通过 HTTP。组件使用同一输入输出类型。业务端不加载 seed、不运行浏览器结算，不在请求失败时回退到样本。React Query 以账号、资源和筛选条件作缓存键，操作成功后刷新受影响的列表、明细和统计。保留业务弹窗草稿与错误位置，后端成功后才关闭。

## 身份、持久化和集成

正式登录通过服务端会话识别教务或老师，Cookie 限当前业务主机，写操作校验请求来源及 CSRF。服务端从会话取操作者，按权限点、项目、队组或本人范围查询和写入；家长问卷用限定用途的 token。业务接口返回页面需要的字段。演示身份与正式登录的差异只发生在入口。

业务 ID 稳定，保留工作簿学员 ID；手机号和姓名均不可作为学员唯一键。课节关联学员、老师、权益和课堂报告，订单通过受益人关系关联多个孩子。课时流水记录来源、方向、数量及原因；更正可查到原交易。账户占用与实扣分别查询。通过事务、来源唯一约束及必要的行锁保护同一账户或时段的并发写。

内部日期以现有业务日历口径解释，业务时间来自服务端时钟。附件由后端授权上传并保存对象存储引用。ClassIn 请求在数据库事务外执行；本地业务记录与待处理任务一起提交，按外部操作标识核对结果再重试。接收回调时验签、去重并关联课节。自动结算与异步任务依既有方案使用 PostgreSQL 后台任务；浏览器关闭仍应完成。

## 接口约定与交付顺序

建议按资源提供查询，如 GET /api/students/:id、GET /api/lessons、GET /api/teachers/me/schedule。写入按现有动作提供具体端点，例如 POST /api/orders、POST /api/lessons/:id/reschedule。请求字段以现有表单实际提交值为准，返回实体 ID、变更后的状态或现有页面可展示的业务错误。校验错误定位到原表单；过期锁、余额冲突或已处理记录返回冲突结果，刷新相关数据，不自动重放写操作。

① 双地址、本地数据库、登录及组织范围 → ② 学员、共享订单与流水 → ③ 老师、问卷、时段与排课 → ④ 课堂交付、考勤及外部同步 → ⑤ 服务反馈、薪资、汇总报表。老师端按同一业务链同步接入。开发完成前通过业务入口的开放范围控制可用流程，Demo 继续展示完整功能。每阶段使用开发库及测试身份，不自动部署。

## 01 全局与身份

**01A · 教务工作台**

会话决定账号、角色及范围；搜索和通知按接收者过滤，变更密码校验旧密码。侧栏偏好留在浏览器。

专项验收：从侧栏进入授权模块，收起侧栏；Ctrl/Cmd+K 搜索并打开学员速览；从通知进入关联事项。通过头像菜单进入改密和退出。 相同账号重登看到相同业务范围，搜索结果与详情权限一致。

**01B · 角色预览与演示工具**

预览与重置仅在演示运行环境装载。业务入口读服务端身份；正式角色预览如对授权管理员开放，只允许在其授权内模拟查看。

专项验收：在 Demo 切换角色查看菜单及按钮，使用演示重置恢复样本；设置返回上一个工作位置。 用不同权限角色比较相同页面；演示重置只影响演示存储。

## 02 数据看板

**02A · 运营总览 /**

后端按账号范围和状态聚合，目标列表复用同一筛选条件。

专项验收：查看课节状态、待确认、待处理反馈、同步异常和课时即将用完；点击事项进入带条件的目标列表。 来源数量和目标列表对同一范围、同一时间一致。

**02B · 项目指标与老师利用率**

项目目标保留生效月份，分子分母取同一批课节；利用率另取老师可用时段。沿用 projectMetrics 及看板的计算口径。

专项验收：选择月份及组织范围，查看目标、实消、应出勤与到课，打开明细并导出；切换老师利用率查看对应时间范围和趋势。 导出与当前筛选一致，汇总数字可追到课节；无可用数据时沿用现有空态。

## 03 学员中心

**03A · 学员列表 /students**

列表按范围分页；服务端用稳定学员 ID 和课节 ID 定位。导出查询沿用当前筛选范围。

专项验收：搜索学员 ID 或资料，组合筛选、翻页，点学员打开档案；行内操作沿用其权限和课节条件，取消前先选目标课程。 同名孩子按 ID 分开，取消只作用于所选课节。

**03B · 建档、编辑、导入与导出**

保存学员、项目归属、负责教务和批次结果；保留前端已有字段映射与逐行提示。编辑仅提交改动字段，处理同字段并发修改。

专项验收：打开资料表单填写并保存；导入时使用现有模板、核对解析结果，选择跳过或更新；导出当前筛选结果。 有 ID 的行更新对应人，留空按新增处理；同批次重复提交不重复建档。

**03C · 学员档案 /students/:id · 概述信息**

学员身份与 ClassIn 身份独立建模；待办、转介绍、档案事件、历史修订关联学员 ID。列表、速览和档案读同一份资料。

专项验收：查看基本资料、画像与历史，编辑资料、绑定 ClassIn、发放问卷；从档案打开统计、待办和对应记录，办理后回到当前学员。 两名孩子可以绑定同一外部账号，历史更正保留原因，待办完成有结果记录。

**03D · 课程与教材进度**

课程查询返回课节、报告、教材和附件关联；调课转排课模块，成功后刷新原课节。

专项验收：查看课程列表或日历，打开指定课节查看老师、教材、进度、截图及同步信息；从符合条件的课节发起调课。 从历史课节能打开当次进度，从未来课节调课能带入原安排。

**03E · 服务跟进**

以事件来源 ID 关联服务、反馈、流水及任务；预览不触发对外发送。

专项验收：在学员下登记服务事项、回访、反馈、待办；点击记录打开详情，需处理反馈时进入同一反馈；提醒按现有预览交互展示。 同一事项只出现一次，关联补偿带入正确学员和反馈，放弃编辑沿用现有确认。

**03F · 停课、复课、结课、退款后停用**

选中学员后选择对应业务动作，填写原因，核对影响的未来课节，勾选已与家长沟通并确认。停课或结课取消未来课并保留剩余课时；复课允许重新排课，已取消课程保持取消。退款按账号共享范围清零余额并记录课时流水，关联学员全部停止排课，取消本系统未来ClassIn课节，保留账号历史；不涉及外部群或其他平台，不执行资金支付退款。

**03G · 转介绍、回访和关联补偿**

登记转介绍时选介绍人、日期并填写备注。回访时选星级和节点、填写原文，在支持的星级附图；缺星级或内容时显示表单提示。由反馈发起补偿时带入学员和反馈，保存后核对服务跟进和课时明细。

03F 的状态、受影响课节、占用释放及服务记录在同一事务完成。用一名有未来课程并有余额的学员依次验证停课、复课，另用一个多学员共享账号验证退款清零、所有关联未来课取消、课时流水只记一次，不产生资金支付。03G 的服务事件关联当前学员，服务端验证介绍人及关联反馈归属；测试从另一学员的反馈发起关联时应拒绝。

## 04 课时与订单

**04A · 课时与续费 · 购课和共享**

订单、受益人关系、权益账户独立保存；按订单汇总占用、可用及实消。订单及入账流水同事务提交。

专项验收：从学员档案点加课时，选购买类型及 72／144 课时。共享时在另一位学员下选“共享已有课时”，选择共用学员，核对成员、余额来源及账号绑定提示后确认。后续购课、补偿和赠送计入共享余额。 两名受益学员看到同一订单；其中一人占用课时后另一人的可用量同步变化。

**04B · 期初余额、加课时、手动扣减**

账户内串行更新，流水记录来源、受益学员、操作者、原因；业务请求重复提交仅记一次。

专项验收：待核余额先录入初始值及原因；先核对当前学员的个人或共享余额，再加课时或输入扣减数及原因，保存后核对明细。 扣减前后余额与流水对应，失败无余额变化，共享扣减能看到所属订单。

## 05 家长问卷

**05A · 发放与填写 /intake/:token**

将开发服务收件迁入 API；按令牌定位问卷，提交原答、状态和画像更新保持一致；只向家长返回本次填写所需字段。

专项验收：教务在概述生成并复制链接；家长独立打开填写提交；教务重开档案查看原答及回填画像。 两台设备分别发放和填写，重复提交及作废链接得到现有提示。

## 06 老师中心

**06A · 老师列表 /teachers**

老师档案关联负责人、办公室、标签及媒体引用；保留现有表单和文件限制。

专项验收：按资料和状态筛选、配置可见列，查看老师资料或打开档案；在管理入口保存档案、TM、SO、标签、展示照片和视频。 编辑后列表和详情同步，媒体重新登录仍可查看。

**06B · 老师详情 /teachers/:id**

周模板、具体日期、请假和课节分表；从同一老师关联课表、考勤、反馈。离职按当前领域规则处理关联业务。

专项验收：切换可上课时间、课表、学员、考勤、反馈、培训记录；在周历勾选可用时间，登记请假，按详情操作处理离职。 请假登记后查看负责教务的跟进通知，原课程按 Demo 规则保留。

## 07 排课

**07A · /schedule · 老师排课与待排课学员**

按日期范围查询时段、已排课程和有效锁，学员候选考虑项目权限与剩余权益。

专项验收：切换老师排课或待排课学员；按日期、老师看周／日视图，从老师时段或学员进入排课面板。 两条入口带入各自上下文，选中的学员、日期和老师与最终课节对应。

**07B · 固定排课、临时排课与课程计划**

事务内重新检查时间重叠、锁有效期、余额及学员冲突，写计划、课节和占用；保留 fixedPlans、teacherMatch、scheduleCredits 的业务语义。

专项验收：填写排课意向，在固定排课选择老师优先或时间优先，核对匹配及覆盖周次，锁定或释放；临时排课从日历选择可用课次，核对计划和课时后提交。 同时占用同一老师同一时段只能一方成功；成功的课节占用正确权益并释放相应锁。

**07C · 调课、取消及换师**

一次事务完成时段变更、释放或重占、课时调整及审计；同步 ClassIn 的结果单独记录。

专项验收：从课表或学员记录选中课节，打开对应操作，核对原安排、填写新安排或原因，确认后回到原上下文。 新旧时间、老师、占用及变更历史对应同一课程；有未保存修改时按原交互处理。

## 08 上课记录

**08A · /lessons · 全部与待确认**

保存考勤事实、异常记录、判定与更正；课节状态变更和课时流水原子提交。自动结算按业务时钟执行。

专项验收：按学员、老师及课节条件查询，切换待确认，打开课节核对到堂、异常、课堂依据，按页面可用动作确认、更正或跟进。 确认后状态和对应扣返一致；已处理课节再次打开能看到原因及处理人。

## 09 反馈

**09A · /feedback · 反馈记录与处理记录**

反馈关联学员、老师、课节及分类；建立受权限约束的列表与工作簿导出。当前Demo没有反馈批量导入入口。

专项验收：筛选并查看反馈全文、分类与处理进度，配置列并导出；新建或编辑后进入对应详情。 列表和学员档案指向同一个反馈；当前条件和导出内容一致。

**09B · /feedback/:id · 跟进与判定**

分别保存客服进度、TM 结论和历史事件；薪资按判定来源计入一次。

专项验收：查看原始反馈及历史；按权限登记客服处理、跟进措施和 TM 判定。关联奖惩或补偿时核对来源。 客服完成只改变处理结果；符合规则的 TM 判定进入当期奖惩。

## 10 薪资

**10A · /payroll · 月度薪资与单价**

保留历史工资单算法及单价有效范围；调整保留金额与原因。

专项验收：选择月份和老师，打开工资明细核对课酬来源、计薪课程和扣款，按状态调整、确认；在单价页查看和维护对应项目。 金额能回溯到来源，确认状态及已产生的明细重读一致。

**10B · 老师与 SO 对账**

复用 officePay 的来源及计算规则；按老师和月份保存条款、来源明细与确认快照；老师端只返回本人可见款项。

专项验收：选择老师和月份，设置 OP／NP 及对应时薪，核对确认时段或完课、奖惩和调整，确认后查看冻结账单。 分别核对老师与 SO 金额；更改后续费率不会改写已冻结月份。

## 11 设置

**11A · /settings · 团队账号、角色与权限**

账号、角色、授予范围分开保存；所有列表、操作和导出在 API 校验同一权限。

专项验收：选择账号或角色，编辑分配、权限点及数据范围，保存后用受影响账号核对菜单、按钮及可见数据。 同名组以所属队区分，直接打开详情也遵守项目和队组范围。

**11B · 项目与渠道、基础资料、业务规则**

目录使用稳定 ID 和父子关系；校验引用及删除规则；历史计算保留有效期或快照。

专项验收：在相应页签选择条目，新建或编辑；项目关联渠道和月应上课数；基础资料维护分类树；在业务规则中调整现有参数。 回到引用页面能选到新条目，历史指标保留原月份依据。

**11C · ClassIn 同步管理、操作日志**

后端保管凭证，按课节和操作去重；记录外部标识、尝试结果与操作人。

专项验收：从同步异常或课节链接定位课程，核对异常，按当前动作重试或关联；打开日志核对操作。 重复处理不创建第二节外部课；完成后来源页与设置页显示同一状态。

## 12 老师端

**12A · /teacher · 今日、课表、课节详情**

会话绑定老师 ID，按本人授课范围查询；各视图复用课程详情。

专项验收：今日打开某节课或进入课表切换日期，从课节查看教材、学员画像、近期报告，可进入学员或结课。 从不同入口打开同一课节，显示相同时间和学员。

**12B · 学员列表、学员详情、结课**

保存媒体引用、课堂报告、课节及学员进度；同课节提交不重复结算。

专项验收：从列表进入本人学员查看上次进度及反馈；在课程详情发起结课，上传教材结束页截图，填教材进度、评价等，提交返回今日。 缺截图时显示提示；成功后教务可在学员课程中查看同一张截图和进度。

**12C · 可上课时间、请假、考勤**

老师仅维护本人时段和请假；老师中心及排课模块共享同一可用时间数据。

专项验收：编辑周历后保存；输入请假起止及原因并提交；进入考勤按月核对相关课节。 结束不晚于开始或缺原因时按原表单提示；教务端能读到已提交请假。

**12D · 反馈、培训、报告、薪资**

培训进度归账号，报告聚合本人课节和反馈；保留历史工资和确认账单两种读取逻辑。

专项验收：进入反馈查看涉及本人的处理结果，经现有入口查看薪资；按培训步骤作答并查看完成状态；进入报告及薪资按页面周期核对指标和来源。 老师只见本人可见内容；冻结工资与后台本人部分一致。

**12E · 消息与账号**

消息已读按接收者记录；改密、退出走身份服务，展示名称来自本人档案。

专项验收：打开消息逐条查看并跳转，或全部标记已读；账号中切换语言、修改密码或退出。 已读后未读数变化，退出后受限数据不可再取，语言切换保留当前业务语义。

## 第一条流程的接口及事务验收

以下路径为拟定接口，沿用地图 01A、03A、03B、04A、04B 的现有表单和入口。

| 请求 | 输入与权限 | 提交结果与验收 |
|---|---|---|
| POST /api/session；GET /api/me | 登录凭据；服务端读取账号授权 | 返回当前身份、权限点、组织范围。刷新后保留会话；退出后不能再读取学员 |
| GET /api/students | 搜索、项目等当前筛选、分页 | 先限制可见范围再过滤，返回列表和总数；与导出查询对照 |
| POST /api/students | 当前建档表单，校验项目归属和新增权限 | 生成学员 ID，返回新档案；同手机号的两个孩子分别可检索 |
| POST /api/orders | 当前学员、72 或 144 课时、业务日期、类型、备注及请求标识 | 第一笔新购建立权益和入账；已有共享余额按页面现有购课逻辑入账，重复提交只产生一次业务结果 |
| POST /api/orders/:id/members | 当前加入学员及需要绑定的账号 | 重算预览依据，校验成员和余额来源后一次性合并；两名学员重读得到同一成员及余额 |
| GET /api/students/:id/credits | 学员读取权限 | 返回账户、已占用、流水及关联订单；与详情和速览核对 |
| POST /api/students/:id/credit-adjustments | 类型、数量、原因及可选反馈；扣减另验对应权限 | 校验余额与反馈归属，流水及余额同事务保存。故意制造冲突后检查无半笔交易 |

## 跨端验收与放行

1. 两名不同队组的教务分别登录，以同名组、同手机号的两个孩子建档；从列表、直达详情、搜索及导出核对范围。Demo 地址执行相同操作，业务库记录数不变。

2. 两个孩子共享 144 节订单，各排一节 25 分钟课，可用量为 142；满足提前取消条件时撤销一节，可用量回到 143。两人同时抢同一档期只能有一笔成功。重复点击购课、结课或同步都核对数据库来源记录。

3. 老师提交结束页截图后，在教务端打开同一课节；确认进度、状态、占用与实扣。登记反馈，分别操作客服处理和 TM 判定，冻结薪资后从老师端逐项对账。

4. 分别模拟业务 API 失败、ClassIn 超时及重复回调。保留当前表单和课节，失败不显示业务成功。正式 ClassIn 回调和外部文件存储在集成环境单独验收。

验收按本次涉及的模块选择既有专项用例，加一条从页面到测试数据库的主路径。历史验收记录含已知失败，旧断言与当前页面不一致时，以当前可操作行为记录差异，保持 UI 并核实业务口径。正式费率、多孩奖归属、机构 ClassIn 回调需要真实样单或机构环境，不能从演示数值推定。

参考：[历史专项验收记录](分模块改造验收记录-2026-11-11.md)、[共享领域规则](../packages/shared/src/domain.ts)、[教务组件专项测试](../apps/admin/src/__tests__)。

## 2026-11-18 确认后的实现规则（覆盖早期同名条目）

退款按账号共享范围清零课时并生成课时流水，关联学员全部停止排课，取消本系统未来ClassIn课节，保留账号历史；没有资金支付退款或外部群/其他平台停用。

账号绑定采用官方register：明确提示、账号持有人同意、初始密码仅新账号生效，学生/老师分别加入机构对应角色。老师classInUid持久化并用于排课，变更后未来课节同步。

课程未知结果仅在有course.create阶段证据时允许用户显式重试固定唯一标识恢复courseId；课节ID未知仍缺外部读取契约，不自动重建。详见ClassIn接口契约核对与阻塞清单.md。

反馈页面当前Demo只有导出，无批量导入；功能地图原“导入导出”误列已按实际页面更正，不新增产品入口。

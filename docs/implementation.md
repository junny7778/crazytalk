# Crazy Talk Demo 实作记录

目标为业务运营构建可交互演示，覆盖后台一期及老师端二期页面。仅模拟业务数据，不调用机构服务。

## 工作顺序

- [x] Ground。依据已核对的业务文档，独立新建工程。
- [x] Sketch。比较两个独立架构候选。
- [x] Agree。选择共享状态及接口契约。
- [x] Implement。分业务闭环实作与专项验证。
- [x] Scrap。未发现需要推翻架构的重复结构问题；修复验证发现的局部业务缺口。

## 执行约束

- 阻塞前置工作为共享模型、操作契约、token 与组件 API。
- 独立工作流为学员与看板、排班、业务管理、老师端。共享文件由主 Agent 维护。
- 共享业务状态只有一个写入入口。并行 Agent 只写各自页面目录。
- 首个闭环前顺序实现基础，契约稳定后再并行页面。
- 页面展示业务结果、依据、影响和下一步。接口、队列、数据库等实现信息不进入运营流程。
- 以可验证单元推进。专项验证通过后继续，不为每次迭代执行全量回归。

## 并行实现记录

Frame → Fan out → Aggregate → Report。按独立目录分工，汇总每个实现与验证结果。
